# 录音整理管家

当前版本：**3.1.0**（会议纪要版）

本项目把录音收件箱、faster-whisper、Ollama/Qwen 和 Obsidian 串成一套本地工作流：录音进入 `inbox` 后自动转写，Qwen 从转写中提取会议主题并整理纪要，最后归档原始录音、转写和纪要。

## 会议纪要内容

Qwen 按转写整理“发生了什么事、决定与结论、待办事项、风险与注意事项、待确认问题”。它需要区分提议和已决定事项；录音没有说明负责人或期限时标为“未明确”，听辨不清的人名、金额、日期等标为“待核实”。原始转写文件保持原样。纠错只针对有上下文支持的日常口语错字、同音误写和重复口头语，不做学科术语纠正，也不通过维基百科补充会议内容。

纪要按 8000 字符切段、相邻段重叠 1200 字符；各段分别整理后按小节拼接，只删除逐字相同的重复条目。相似但不完全相同的事项会保留，避免把不同责任人、期限或条件误合并。

## 文件命名与时间说明

归档文件使用 `YYYY-MM-DD_HH-mm_会议主题`。程序优先读取录音文件名中可识别的日期时间，否则使用文件修改时间；实际采用的时间和来源写入原材料旁的 `.meta.json`，转写和纪要中也会标明。

**文件名时间或文件修改时间不一定等于会议开始时间。** 只有录音文件名提供了可识别时间时，程序才把它作为文件名时间；程序不会把它宣称为经过核实的会议开始时间。主题无法提取时使用“未命名会议”；同名文件自动追加 `_2`、`_3`，不覆盖已有内容。

所有录音均归档到统一的 `会议/{原材料,转写,纪要}` 目录，不进行学科或会议类型分类。

## 本地运行

需要 Windows、Python 3.11+、Ollama、一个 Qwen 模型和 faster-whisper 所需模型文件。首次运行需要联网安装依赖、下载模型；音频和纪要在本机处理。

```bash
python -m pip install -r requirements.txt
ollama pull qwen2.5:7b
```

将 faster-whisper 模型放入 `models/`，复制 `config.example.json` 为 `config.json`，按本机目录调整收件箱、Obsidian vault、模型路径和 Ollama 地址，再运行：

```bash
python src/app.py
```

`config.example.json` 只含通用路径和模型设置，不含真实录音、Vault 路径或模型权重。桌面图标资源为项目根目录的 `icon.ico`。

## 目录结构

```text
src/
  app.py          桌面界面与录音监视
  core.py         转写、Qwen 纪要、归档与去重
  rerun_note.py   基于已归档转写重新生成纪要
tests/            隔离文本与归档测试
docs/             架构、安装与维护说明
config.example.json
icon.ico          与原版一致的应用图标
```

## 资源说明

转写与纪要仍按原有顺序执行，转写模型会在纪要阶段前释放显存。本项目不包含 Python、Ollama 或模型权重；使用者需自行安装并准备这些组件。当前没有真实会议录音的端到端质量基准，使用者应抽查转写与纪要，尤其核对人名、数字、决定和待办。
