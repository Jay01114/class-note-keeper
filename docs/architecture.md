# 架构说明（3.1.0）

## 数据流

```text
录音文件 → inbox 稳定性检查 → faster-whisper 转写（保留原文）
         → 8000 字符切段、1200 字符重叠 → Ollama/Qwen 按段整理会议纪要
         → 精确去重和归档到 Obsidian
```

现有 UI、转写参数、轮询与队列调度沿用 3.0。转写和 Qwen 纪要仍串行执行；转写后释放 Whisper 显存。

## 会议纪要

Qwen 元数据请求只提取 `TOPIC` 和 `TITLE`，不做学科识别或会议类型分类。纪要小节为：发生了什么事、决定与结论、待办事项、风险与注意事项、待确认问题。每段独立整理后按标题拼接；程序仅删除完全相同的条目，不按相似度合并。建议与决定分开；不明确的负责人、期限或事实不得猜测。

原始转写文件保留语音识别输出。Qwen 的口语纠错只用于整理纪要，不进行学科术语表替换。纪要不查询维基或其他外部知识源。

## 归档与时间

归档目录固定为 `vault/会议/{原材料,转写,纪要}`。文件名格式为 `YYYY-MM-DD_HH-mm_会议主题`；重名追加 `_2` 等后缀，避免覆盖。

程序优先从源录音文件名解析日期时间，否则使用文件修改时间。来源写在原材料旁的 `.meta.json` 中，也会显示在归档文档。**这些文件时间不一定等于会议开始时间**，程序不将其标注为已核实的会议时间。

## 隐私与外部连接

音频、转写与纪要保存在用户配置的本地目录。纪要请求发送给本机配置的 Ollama 服务；本程序不请求维基百科，也不自动补写转写中不存在的事实。
